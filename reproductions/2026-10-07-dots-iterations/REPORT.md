# Dots 风格界面：三轮使用与修正

2026-10-07。用户要求多迭代，不急着给成果。每轮先实际使用，定位问题，再修改和重新验证；保留持续群聊，不添加会议表单或新的工作机制。

## 第一轮：能否直接审查结果

**发现**：活动没有日期和安排编号，同名步骤难以区分；从活动打开已完成步骤时，只显示摘要，完整报告跳到 JSON。研究结论引用产物 ID 时也没有可点的链接。

**修改**：活动按最近结束或启动时间排列，显示日期和安排编号；报告从活动和聊天附件打开同一个可读内容，直接呈现结论、未确认事项、下一步和依据。操作记录与产物引用都可打开。计划原因与模型调用明细折叠保存，没有改写原报告。提高状态与活动说明的字号和对比度。

**重新验证**：在已有本机研究报告上，只读核对发现、限制、建议和引用目标，与保存内容相符；原始证据入口仍可用。程序演示的六份产物可按两个安排区分，未执行步骤另标注。个人研究材料和截图不进入公开仓库。

## 第二轮：讨论能否连续

**复现**：输入未发送内容后刷新，原实现的草稿为空。等待答复时文本框被禁用，不能写下一句。

**修改**：草稿按群保存在当前浏览器标签页的 sessionStorage；刷新及切群恢复。等待期间可写下一句，同一个群的上一条消息处理完前不重复提交；其他群可继续使用。答复完成不会清空后来写的新草稿。未确认的发送保留原编号和内容，刷新不自动重发。恢复按钮只由人点击，使用原编号；已保存记录不再执行一次。新群页面位置也会在刷新后恢复。

**故障注入与重新验证**：独立本机服务只允许 simulation，不接模型或公开检索；固定延迟 5 秒，慢答复场景 15 秒。这些是测试延迟，不是模型速度。

| 场景 | 观察结果 |
| --- | --- |
| 输入后刷新 | 同一草稿恢复；新群尚未发送的想法也恢复 |
| 答复处理中写下一句 | 输入框可编辑，发送按钮暂时禁用；原答复完成后新草稿不被清空 |
| 两个群切换 | 草稿分别保存；旧群答复不出现在新群，未锁住新群 |
| 保存前断连 | 原消息保留；人工恢复后只保存一次，下一句仍保留 |
| 保存后断连 | 从已保存记录恢复，不重新执行；复核消息只保存一次 |
| 慢答复中刷新 | 原请求继续保存结果，页面轮询找回；没有自动重发，后写草稿保留 |

故障验收还发现“保存后断连”可能留下失败提示，已修正为先检查已有记录；找到原记录后提示恢复。每个故障场景在 SQLite 中均只有一条消息。两个验收群模型请求和公开 HTTP 请求均为 0。

## 第三轮：阅读与键盘是否被打断

**发现**：原实现有变化就重建整段聊天 DOM，等待秒数更新也可能让报告控件失去焦点；窄屏打开侧栏时焦点仍在主页面，Tab 可走到遮住的控件。

**修改**：按消息标识保留未变化的节点，更新只影响变化的消息；保持展开内容和阅读锚点，不在答复完成时强拉到底。阅读旧消息时可点击“回到最新消息”。窄屏侧栏让背景暂时不可操作，Tab/Shift+Tab 在侧栏内循环，Esc 关闭后回到原入口；宽屏资料页保持非模态。上下文里的报告也注明日期与安排编号，新结果在前。

**重新验证**：在 390×844 和默认 1280 宽窗口检查，无横向溢出。15 秒慢答复期间展开旧材料、保持焦点；答复到达后，该控件仍展开、焦点标识相同、纵坐标仍为 558.63 像素，阅读滚动位置不变。聊天共 29 个消息节点，标识唯一，没有因替换产生重复。回到最新消息后入口收起。Shift+Tab 从侧栏首控件回到末控件，Tab 回到首控件，Esc 恢复原活动入口。临时尺寸覆盖已撤销。

## 边界与后续

这三轮验证交互与发送恢复，不证明模型答复质量、自主科研或论文复现能力。未新增模型调用、权限、预算或调度机制。报告仍是已有模型解释，原始证据和失败应继续审查。

草稿只保留在当前标签页的会话存储中，不上传服务器；关闭标签页后是否恢复取决于浏览器会话恢复，不能当成项目持久记忆。存储被禁用时只保留当前页面内存。网络完全中断时无法确认服务器是否收到；保留编号并等待恢复，不自动重试。

后续应继续验证真实长答复的可读性、大量历史记录的性能、新群权限说明的易懂程度，以及科研执行器本身的能力；不以当前演示回复替代这些验证。
