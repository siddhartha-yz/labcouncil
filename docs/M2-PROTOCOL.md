# 下一步：把真实 Flash 与一个可核验任务接进平台

状态：受控合成案例部分已实现并实际验收，见 [完整案例记录](../reproductions/2026-10-06-complete-case/REPORT.md)。已接入真实 Flash、固定工具、两轮工作、一次快照问答、请求次数硬上限和正常重启；记录了数值通过但报告描述错误的负结果。实际用户科研评审、文献检索、隔离代码执行、外部副作用恢复和真实费用硬预算仍未完成。以下保留完整 M2 验收要求。M1 默认模拟模式仍保留。

## 用户会得到什么

新建项目时明确选择“模拟演示”或“真实受控计算”。真实模式先限定一个公开、可重复的小任务：比较已有 CSV 上的两种预测方式，并按组会确认改变下一轮输入。页面先用简短中文说明结果与限制，再提供数据、脚本、原始响应和复核入口。

第一项任务用已有合成数据验收工具路径，不能替代代表性科研问题评估。模型可以提出允许的实验参数；平台只执行事先定义的工具。不把任意 shell 命令、自由文字 idea 或模型自称有用的论文直接放入执行环境。

## 从 M1 扩展的边界

- 给项目/任务持久化独立的运行模式和供应商配置引用；每项产物记录真实、模拟或人工来源。供应商配置不包含公开密钥。
- 模型适配器、工具适配器和组会状态分开。真实模式不能静默退回模拟；失败显示具体阶段和可重试范围。
- key 只由本地调用进程读取，网页/API/产物不返回它。公开材料继续使用合成输入。
- 报告完成必须同时有任务输入、实际工具返回、产物内容哈希和独立数值复核；仅模型回复“核验通过”不够。
- 讨论保存为讨论；模型提出下一步也仅为草稿。用户确认才创建下一轮版本；既有确认重放只返回原结果。

M1 的任务与状态表不是最终真实执行 schema。增加字段需要写迁移，并用已有 M1 数据库检查升级后项目、会议与决定不丢失。

## 预算要怎样才算通过

先实现两个可明确验收的硬限制：**模型请求尝试数**和**每次输出上限**。发送前在持久化事务里占用一次尝试额度；并发 worker、网络超时、429 和失败请求都计入，禁止隐藏重试。后台与组会分别计数。

真实 usage 与请求 ID 按每次实际响应保存，分别记录输入、输出、缓存和未知字段。usage 缺失显示未知，不能填0。重启要保留已占额度；不能因为调用失败或产物未保存就退回额度。

token 用量与人民币费用单独显示。仅在响应后累计 token，无法保证某次请求绝不越过剩余 token 上限；没有可靠调用前计量或可证明的预留机制，就必须把 token 硬预算标为未实现。人民币费用没有账单或核实计价则保持未知。M1 的角色单位不转写为真实费用。

## 外部实验恢复

每项执行分配稳定 operation ID，与任务/输入哈希绑定。启动前查询执行端已有状态；恢复先查询结果，再决定连接运行中任务或启动。任务租约仅管理哪个 worker 可以提交，不代表外部实验只执行一次。

保留至少三种故障记录：请求前崩溃、外部已经接受但本地尚未记录、结果已有但产物提交前崩溃。必须验证每种恢复后的实际调用/运行次数和结果 ID。没有执行端去重/查询接口，就不能对不可重复操作承诺自动安全恢复。

组会或工具审批绑定具体请求 ID、输入摘要与阶段。连续批准、第二次否决、过期页面、断线重连和重复发送分别检查。节点恢复不能把上一次批准应用到下一项操作；参见 [InternAgentS 局部诊断](../reproductions/2026-10-06-internagents-approval-component/REPORT.md)。

## 最小验收顺序

1. 不调用模型：供应商 HTTP fixture 检查并发请求上限、超时、429、usage 缺失、重启与无凭据泄漏；fixture 明确标注，不能计作真实模型结果。
2. 实际 Flash：新目录、固定模型、事先保存协议和小请求上限，记录所有成功/失败响应；至少实际完成一个受控计算任务。
3. Reviewer 从保存的数据和参数独立计算，不直接执行模型脚本；数值不一致时任务保持未核验，报告明确显示。
4. 实际浏览器：用户看懂材料并确认不同输入；第二轮实际工具结果改变。Codex 自己的点击可算工程检查，不能冒充真实用户科研评审。
5. 在独立试验实例做中断/恢复，核对证据、额度和操作 ID；不覆盖原失败，不扰动正在展示的 M1。

只有上述对应范围通过才更新 M2 清单。连续长期运行、真实研究质量和人工时间比较仍属于 M3/M4；上游 InternAgent/SCP 是否有必要接入，按具体工具需求继续验证。
