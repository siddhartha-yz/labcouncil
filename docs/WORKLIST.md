## 平台本身必须交付

- [ ] 用户提交 idea，后台产生有证据的任务和报告。
- [ ] 到固定时间准备简短中文组会材料，先解释做了什么、发现什么、不确定什么、需要用户决定什么。
- [ ] 用户能逐条追问、打开原始证据、编辑并确认下一轮方向。
- [ ] 确认后的决定触发下一轮工作；讨论提案和正式决定分开保存。
- [ ] 浏览器关闭后仍能工作；重启后不重复实验、重复派单或丢失决定。
- [ ] 调用前检查预算，记录真实用量，达到上限停止；后台研究和组会问答分别计量。
- [ ] Reviewer 实际复算关键结果，保留失败、未知项与适用范围。

原有12次受控比较已完成，不能把它当成平台已建成。之后还要用代表性真实问题检验组会能否减少方向偏移和重复实验；人工时间未知就保留未知，不补造数字。

## 接下来的顺序

1. InternAgent 最小运行，优先明确它能否作为独立实验执行模块。
2. SCP 最小工具调用，确认它是否能省掉具体工具的接入工作。
3. 推进 M1 本地平台原型，先完成一次组会与两轮工作的完整流程；模拟与真实产物明确区分。
4. 按 M2/M3 接入已验证工具、预算与恢复，再开展真实问题评估。
