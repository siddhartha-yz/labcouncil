# 运行本地组会原型

这个版本采用持续群聊：说想法、讨论已有结果、商量工作安排，在群里同意后后台接着做。网页新群默认 Codex research 后台但权限初始关闭；可选固定程序演示。真实模式可选 Codex CLI（gpt-6.1-sol / high）或 DeepSeek Flash，负责工具参数、报告与组会答复。逐步研究模式根据已保存证据选择公开查询或整理组会；完整论文复现仍未接入。

## 开始使用

需要 Python 3.11 或更新版本。应用本身只有标准库依赖。默认模拟模式不用 API key；Codex 后台复用本机 `codex login`；只有 DeepSeek 后台读取仓库根目录被 Git 忽略的 `.env`。从仓库根目录执行：

```bash
python3 -m labcouncil start
```

然后打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。不要直接打开 HTML 文件。

`start` 在 Linux 上启动独立网页进程和 worker，重复运行会复用本实例。不会注册开机服务。每个实例使用独立运行目录；默认状态位于忽略的 `workspaces/labcouncil/`。

也可以各开一个终端，手动运行：

```bash
python3 -m labcouncil serve
python3 -m labcouncil worker
```

两个命令要使用同一个 `--database`。手动启动的进程用各自终端停止；`start/status/stop` 只管理带本实例标识的后台进程。

## Codex CLI 后台

Linux 上先安装 Codex CLI 并在终端完成 `codex login`。本机已验证 CLI 0.159.0、ChatGPT 登录和实际调用，不需要给网页填写新的 key。

网页新群默认 **Codex CLI · gpt-6.1-sol · high** 逐步研究，在群里明确允许模型调用并同意安排。其他执行器在新建群的“···”中选择。后台按项目保存，下一轮继承；旧项目仍保留 DeepSeek 或模拟配置，不会被迁移成 Codex。需要比较两个后台时创建新群，避免同一项目混用供应商记录。

worker 每次通过参数数组运行 `codex exec`：`--model gpt-6.1-sol --config 'model_reasoning_effort="high"' --sandbox read-only --ignore-user-config --ignore-rules --ephemeral --json --output-schema ... --output-last-message ...`。提示由 stdin 传入；不改全局配置，不传入环境里的 API key，不保存原始 stderr。Codex 内置 shell、浏览器、插件、MCP apps、hooks 和子 agent 等能力关闭；它输出结构化参数，平台校验后执行原有有界工具。**这次是模型后端接入，不是开放任意仓库代码执行。** read-only 也不等于完整的文件读取隔离；以后开放代码执行需单独设计隔离工作区。

每次 CLI 启动前在 SQLite 占一个调用槽；后台与组会分别计量。一次启动可能包含多个内部模型 turn，CLI 自身可能处理连接恢复；启动次数上限不等于 API 请求数、token 或费用硬预算。CLI 返回的 input/output/cache/reasoning usage 保存，缺失保留未知，费用未知。规划和固定工具阶段最多120秒，研究报告与组会答复最多180秒；超时杀死进程组，失败占额度，不由平台自动重试或更换模型。Linux parent-death launcher 在 worker 消失时终止 CLI，租约过期按真实任务失败/未知处理。research 的 Codex 任务租约600秒、固定案例300秒，为两次CLI及原有短工具留出收尾时间。

每次任务和追问根据本轮输入、旧报告和固定证据重新构造上下文；CLI 会话是 ephemeral，项目记忆仍由 LabCouncil 的 SQLite 管理，不依赖 `resume --last`。保存 `thread_id`、正常化事件、最终 JSON 和用量；当前事件流不能独立证明服务端实际模型，证据是显式参数且无降级逻辑。

真实验收见 [Codex 后台记录](../reproductions/2026-10-07-codex-backend/REPORT.md)：两轮四步、一次实际组会答复、九次CLI启动，保留首次适配错误。方向确认由验收脚本完成，不能当作用户科研评审。

## 真实 Flash 合成案例

在本机 `.env` 配置 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL=deepseek-flash`，不要把 key 粘贴到项目想法或聊天里。新建群的“···”中选择“固定计算”和“DeepSeek Flash”，再在群里授权模型与本地计算并同意安排。这会产生实际 API 请求与可能的费用。

第一轮选择干净数据；三个角色各执行两次模型请求：请求指定工具，再依据真实结果写报告。工具只有数据准备、回归计算、独立复算三项；40 个训练点、100 个独立测试点。组会确认“测试集含异常点：三次重复”后，第二轮测试标签约一成加入异常点，训练数据保持不变。自由文字决定会传给模型，但工具能力仍限于所选场景。

网页默认后台请求硬上限12；组会问答不设累计次数或模型请求次数上限，已有项目也适用。后台请求与角色任务单位分开计数；失败、超时和未知后台请求都占额度，不自动重试。后台额度建项目时设定，当前设置页不能提高后台真实请求额度。组会请求仍保存尝试、结果和用量，仍需授权模型调用，持续群聊不要求先建立组会；旧组会问答API仍检查是否结束。旧数据库/API中的 qa_budget 与 qa_api_budget 保留兼容，但不再用于阻止问答。响应 usage 原样保存；缺失显示未知。每次输出上限768 tokens，不是整个项目 token 硬预算，人民币费用也保持未知。

报告中的“复核通过”仅表示数值从原始数据复算一致，**不能保证模型的每句话准确**。完整案例中，计算与复核角色把异常点数据误写成干净数据；原文仍保存，页面把实际工具输入并排显示。修订后的上下文会明确传入场景参数，但尚未再次用真实模型验证是否改善表述。

实际记录见 [完整案例](../reproductions/2026-10-06-complete-case/REPORT.md)。组会追问是实际 Flash 输出；Codex 点击确认的方向明确标为工程 fixture，不冒充你的科研评审。

## 持续群聊

页面参考 Dots 的聊天与活动结构：点击顶部 LabCouncil 名称或头像打开资料页，查看活动、上下文、工具权限与设置；右上角时钟直接打开活动，左上角展开研究群列表。长答复可展开完整原文，原始证据与调用记录继续保留。消息框加号可以补充资源和要求，不代表已接入文件上传。[设计与范围](DOTS-DESIGN.md)列出官方参考及未实现的能力。

默认页面只保留消息输入与发送。直接讨论进展、交代工作、补充资源或要求，不需要先点“开组会 / 下一轮方向 / 工作条件”。新建群时发送 idea 即建立项目；默认 Codex CLI research 后台，模型、本地计算和公开查询权限初始关闭。可在新建群的“···”中选择程序演示或其他后台，已有项目不自动切换执行器。

明确交代“接下来先核对……”会直接在当前权限与预算内安排工作，同时留下复述。讨论、假设或尚未决定的想法形成提议，在群里同意后才执行；补充条件会更新安排，普通问答不会启动工作。“暂停一下”停止启动新步骤，“恢复工作”沿用原安排和原计时；“取消安排”撤回待执行提议。正在执行步骤时同意新安排，会先保存当前步骤，然后自动切换，不丢弃已有记录。上下文、权限和项目累计消耗上限继续保留，不会通过聊天自动增加额度。

五项输入是后台记录，不再是必须逐项填写的表单。权限需要明确语句，比如“允许模型调用”“允许查询公开论文与仓库”“禁止本地计算”；模型不能自行提高权限。时间可说“最多工作30分钟”或“先花半小时”。资源与要求可直接说明，由协调助手整理到待同意安排；不能识别或有歧义时继续聊清楚，不执行任意 shell、安装、发布或任意私人文件读取。

每次提问使用消息到达时保存的资料，答复保留当时的证据 ID 和调用记录。下一条消息可以使用后来完成的报告，旧答复和旧组会快照不会改写。历史组会通过附件回看；旧 API 仍可读写原有组会，但主界面不要求进入某场组会。尚无证据也可讨论状态与计划；不能凭空声称完成复现。

工作时长仍是投入上限，默认120分钟，1–10080分钟。新预算从安排实际开始起算；改方向沿用当前截止时间，只有明确补充新时长才重新计时。首次未开始工作也从安排生效起计时；等待当前步骤保存不扣新预算。暂停和服务离线计入，重启不重置。截止后停止追加步骤，已开始步骤可保存。每轮最多六步和项目累计任务、模型、公开HTTP上限继续生效，可能提前结束。新的安排不自动增加项目累计额度。

旧输入、规划、讨论和组会快照保留。旧每日时段停止作为启动条件，旧轮按原确认时间加默认120分钟解释，不默默延长。服务重启保留待同意或已同意但等待交接的安排。相同消息编号重复提交只返回原答复；响应失败、断线或调用状态未知不会自动再发模型请求。

详细执行约定见[持续群聊](CONTINUOUS-CHAT.md)。历史网页验收文档保留当时的界面，不代表当前仍需要按钮流程。

## 逐步研究模式（仍在验收）

新建群时可在“···”选择逐步研究后台，在群里明确允许模型调用及公开查询权限并同意工作安排。每轮投入预算继续生效；本地计算权限可以不勾选。报告解释做了什么、发现什么、未完成项和下一步建议。每一步的规划、原因、真实工具状态、来源和模型原始响应在展开证据中。

目前工具范围：arXiv检索/摘要、GitHub搜索/固定commit README、自有OLS合成基准、准备组会。模型在这些动作中选择下一步，后台保存结果后才派下一步；每步2次模型请求，每轮最多6步，公开HTTP总上限建项目时可设0–24次，失败或未知均计入。默认不重试；明确勾选“连接失败后允许重试”时，每个URL整个项目最多三次尝试，2秒退避，仍受项目总上限约束。HTTP拒绝、证书校验失败、started/unknown不重试。连接方式、序号、耗时和结果留在账本。已成功操作跨轮去重；新一轮允许重试时可再检查前轮失败资料，同轮重复仍停止；关闭重试不丢失此前成功的缓存。公开资料不当作指令，不运行其中代码，不读取任意网址。

模型报告失败时，工具证据仍可审查，组会快照也保留当时已有工具记录。提示上下文标明节选，最多15000 UTF-8字节，完整原文保存在数据库；没有按需查询全部记忆的工具。

[真实验收](../reproductions/2026-10-06-research-loop/REPORT.md)确认逐步选择、失败留痕、自动停止、组会继承。公开查询多次TLS错误，前台独立检查只读到仓库元信息，未取得完整README。因此目前不能承诺公开检索稳定，更不能说论文已复现。

研究任务租约五分钟（固定案例仍为三分钟）。每步通常最多三次公开请求；明确允许连接重试时最多九次。arXiv仍全局串行并间隔三秒。达到公开读取额度后停止继续派任务，等组会审查；历史项目自动迁移默认24次，不改变模型额度和原有输入。

组会综合报告会固定本轮工具证据和最多3条前轮操作，每条发现可打开依据；更早记录仍在历史里。工具已保存而模型报告失败时，证据仍可引用。页面区分新读取和旧资料复用。报告与问答收到当前额度、权限及未接入工具信息，但引用有效不保证文字结论正确，仍需审查来源范围和建议是否可执行。

投入与有效进展为何分开、哪些指标已可测，见[工作量控制](WORKLOAD-CONTROL.md)。
