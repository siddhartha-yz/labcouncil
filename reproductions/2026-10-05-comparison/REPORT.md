# 三种工作方式的小范围比较

日期：2026-10-05，Asia/Shanghai。[预注册](PROTOCOL.md)、[逐运行验收](assessment-final.json)、[用户原始反馈](human-feedback.json)。

这次让模型做的是两道很简单、能核对答案的计算题：比较“从训练数据学出直线规律”的方法和“始终预测训练集平均值”的方法。第一题的数据正常；第二题在测试数据里故意加入少量错误标签，训练数据不变。每个随机样本都重新算其自己的基线，不拿旧样本的分数代替新对照。

**结果没有证明人工组会或多 agent 普遍更强。** 在这次受控任务中，多角色更常主动补齐三个样本和三种误差指标；但它们没有完成对新证据的独立核验。单角色有两次核验了报告引用的全部证据，却只做了一个样本。覆盖更多数据和检查已有数据是不同能力，不能合成一个宣传分数。

## 实际结果

每组两个任务、每个任务重复两次，共四个运行。12 个运行全部完成，没有模型/工具错误或自动重试。表中是达成次数，分母都是 4。

| 条件 | 报告数字与原始文件一致 | 三个随机样本、三种指标都覆盖 | 报告引用的证据全部经过 agent 调用核验工具 | 实际模型请求 |
| --- | --- | --- | --- | --- |
| 一个 agent 执行、自查和修订 | 4/4 | 2/4 | 2/4 | 24 |
| executor 与独立 reviewer，没人类组会 | 4/4 | 4/4 | 0/4 | 20 |
| 两个角色，加用户真实组会意见 | 4/4 | 4/4 | 0/4 | 20 |

多角色和人工组没有虚构核验 ID：它们的 verification_refs 是空列表，报告说明没有独立核验；不能把“没核验”写成“谎称核验”。全部原始 CSV 后来由宿主独立复算通过，但这不计作 agent 自己完成了检查。

实际使用 64 次请求，输入 72,212、输出 15,923、合计 88,135 token；预注册最多72次。单角色每运行六次；另外两组 reviewer 直接出报告而没有调用工具，因此每运行实际五次。共享的是相同最大预算，实际消耗不同，不能称完全相同的 token 成本。

所有组使用同一模型 deepseek-flash、同一工具、数据生成方法、最大六次请求、每次1024输出 token、最多两项新实验和六个 seed 计算单位。温度0.3，服务端随机性不可控。Python 3.14.4（详见各 state），第一份工具验证曾用其他 Python，这次三个条件一致。

## 用户确实参与了什么

先生成四份初稿，保存工作进度，等待用户意见。用户选择“认可当前有限结论，按 agent 自己的方案继续”，同时反馈“这阅读材料都不说人话。” 记录原文并解释为需要易懂中文报告，没有替用户编造新的实验方向。随后真实 reviewer / executor 继续工作，报告改用了中文说明。

这轮用户给的是有限认可，而不是具体科研纠错意见；与无人工组的覆盖结果相同，不能证明有针对性的专业反馈没有价值。问题提供了可选答案，属于有提示的人工评审，不是无引导评审。评审耗时未提供，记为未知；无法完成包含人工时间的成本效率比较。

模型把语气变为“大白话”但仍保留大量术语和小数，界面后续应给短摘要，把完整参数放进可展开证据。用户可读性没有通过独立测量。

## 方法和解释限制

计算工具已经实现正确的数据分割、匹配基线和保存逻辑；本试验主要检查模型如何选下一步、引用和核验结果，不能证明它能独立写出正确实验代码。任务很容易，三个条件都收到初稿的有限种子信息和明确允许范围。两次重复只能发现工程问题，不能估计稳定成功率或进行优越性检验。

例如，人工组 outliers 第二份结论把较低误差称为“更抗离群标签”。本试验的训练数据始终干净，只改变测试标签；它没有比较训练时的鲁棒损失或抗异常拟合能力。因此更准确的解释仅是这些测试条件下的预测误差更小。这是 Codex 的语义复核，不冒充用户额外评审。

评分初版把“所有证据核验完成”命名为 verification_claim_supported，混淆了无核验与虚构核验。保留 [原评分结果](assessment-before-human.json) 和 [原 runner](runner-original.py)，离线复评拆成两个字段，没有重跑模型或改变原 state。修订后的四项验收测试检查错误基线、伪核验、布尔数值和缺失样本均不能获得错误通过。

## 记录与复跑

[runs](runs/) 保存每次请求与响应、各阶段报告、真实 CSV、计算参数、hash、工具事件和状态；认证头及 key 不进入记录。全部已保存的实验使用独立 raw-moment 拟合公式复算，验证文件哈希、预测和每一项指标。宿主核验与 agent 核验分开。

```bash
python3 reproductions/check_comparison.py --mode nonhuman --output /path/to/new/runs
python3 reproductions/check_comparison.py --mode human-drafts --output /path/to/new/runs
# 读取初稿，填写真实 feedback，才能继续：不要把演示文本冒充用户意见。
python3 reproductions/check_comparison.py --mode human-finish --output /path/to/new/runs --feedback /path/to/actual-feedback.json
```

运行前填写忽略的 .env，deepseek-flash 不得换成 Pro；输出目录不能已有同名运行。human 反馈允许分钟数未知，不视为零；发生错误会保留失败并继续其他预注册样本，不重试到成功。

## 对平台的决定

继续采用“模型提出下一步 + 真实工具产出证据 + 明确验收”的有限流程。核验必须作为完成条件单独检查，不能仅在角色提示里建议；用户认可也不能绕过该条件。用户反馈进入持久化工作进度的流程已经实际走通，但尚未构成定时组会 Web 平台，且没有证明研究能力的普遍提升。
