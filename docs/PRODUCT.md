# LabCouncil 的三步循环

2026-10-06，按用户确认的意图对齐。工作时间指每天固定时段。

## 用户的输入

每轮使用同一套输入，而不是只在项目开始填写一次：

| 输入 | 用途 |
| --- | --- |
| Idea | 本轮要解决的问题、希望得到的结果 |
| 可调用资源 | 已接入的模型、调用额度、计算环境、数据、论文与仓库 |
| 权限 | 哪些工具和操作允许执行；资源可用不等于所有操作都获准 |
| 每日工作时间 | 哪个时区、每天什么时候可以开始新任务 |
| 额外要求 | 方法约束、交付物、停止条件与报告偏好 |

新项目生成第一版输入。组会之后回到这一页，继承原有内容；用户只修改需要调整的部分。确认生成下一版，既有版本不改写。项目名称属于可选的辅助信息。

## 后台应完成的工作

协调 agent 根据可用时间、资源、权限和已有上下文安排颗粒度与计划。长任务拆成可检查、可恢复的小任务；下一次启动前检查工作时段、权限与额度。已开始的工作收尾并保存。

专业任务探索相关论文和仓库，保留来源与版本；对拟采用的结果做复现，记录失败和未确认项；整理代码、输入、实验数据、指标与结论。已经完成或被否决的工作不得因为新一轮对话重复执行。

后台在边界内自动 loop：保存一次尝试和证据，评估下一项有价值的任务，再继续。它不等于固定时间重复同一个计算，也不等于创建相同任务刷进度。缺资源或权限、额度用完、没有有效下一步时，保留状态等待用户。

报告首先用大白话说明“做了什么、发现什么、还有什么没做、需要决定什么”。来源、数据和技术明细按需打开。数值核验范围与模型文字准确性分别说明。

## 用户开组会，再进入下一轮

用户选择“开组会”，审查当时的报告、追问并打开证据。讨论与正式决定分开保存。之后回到五项输入；保存草稿不派单，确认才启动下一轮。旧规划、来源、实验、失败、报告、问题和决定仍属于同一个项目。

完整上下文持久化；传给模型的是可追溯的节选与引用，而不是要求每次把整个项目塞进 prompt。完整研究执行器还需要按需读取原始记录的工具。

## 界面与当前实现

前端只突出三步、本轮目标、规划、报告和组会入口。角色、调用日志、原始证据与执行器配置放到展开项。避免为装饰增加头像、动画、虚拟房间或大块仪表盘。

已实现：五项输入的版本保存；每日时段（含跨午夜与时区）；模型和已接入本地计算权限检查；组会后返回继承输入；草稿与决定持久化；旧上下文与证据保留；本轮报告和原始记录入口。

当前执行器仍是固定计算工具链，执行计划由程序生成。真实 Flash 模式支持该工具链的调用和报告。通用的资源感知规划、论文/仓库探索、任意复现实验与持续研究 loop 尚未接入；资源说明和公开研究权限不能自动激活这些能力。界面闭环通过不等于整个研究平台完成。

下一项交付应补齐第2步的实际研究能力，使用明确问题、授权资源和预算验收。原有论文与仓库候选仍按 [WORKLIST.md](WORKLIST.md) 保留和验证。
