# Dots 交互参考与 LabCouncil 适配

2026-10-07，用户要求先参考 Dots 的设计重做，再讨论微调。本版先实现可以运行的聊天与资料页，保留现有研究执行器及证据账本。

- [中文发布介绍](https://openai.com/zh-Hans-CN/index/introducing-dots/)：持续协作，后台推进，主动汇报，需要时参与决策。
- [入门指南](https://help.openai.com/zh-hans-cn/articles/20001530-getting-started-with-your-dot)：从名称或头像进入资料页，查看活动、上下文和控制选项，随时暂停。

这些公开图示没有展示完整产品，也没有公开调度、记忆或自动审查的源码。当前是根据可见设计与说明的适配，不声称逐像素完整复刻或实现同等能力。官方图仅在本机查看，没有复制进仓库。LabCouncil 的小角色由本地 CSS 绘制。

## 当前实现

| 参考结构 | LabCouncil 行为 |
| --- | --- |
| 持续聊天 | 同一个输入框讨论、交代工作、反馈；不要求进入会议或下一轮页面 |
| 头像与名字打开资料 | 点 LabCouncil 查看进展、成果与资料、设置；研究群列表默认收起 |
| 工作持续有记录 | 活动来自真实任务状态；排队与未执行不能显示成正在工作 |
| 当前与过往活动 | 展示正在进行、等待中、等你决定、定时整理材料、过往活动；失败与未执行独立标记 |
| 在消息里带成果 | 专业角色继续汇报，附件打开报告；答复的依据和调用明细保留 |
| 反馈与控制 | 群聊授权与工作安排继续按已有规则；资料页可以暂停或恢复新任务启动 |
| 简洁的消息框 | 圆角消息与单行起步输入；加号补充资源、要求或查看活动 |

活动是项目内的执行记录，不是一个新的工作调度器。已有定时入口只定时整理材料；未增加通用周期任务、云电脑、文件上传、语音或应用连接。设置中明确显示未接入能力。上下文直接来自项目记录，不冒充自动学习的长期记忆。

发送后立即显示待服务确认的消息；服务已保存的处理中消息显示等待状态和实际等待秒数。收到答复后显示实际模型耗时或“本机系统回执 / 未调用模型”。没有虚构思考过程。未发送草稿按群保存在当前标签页的会话存储，刷新可恢复；等待答复时可先写下一句。未确认的发送保留原编号，先检查保存记录，再由人点击恢复；刷新不自动重发，已有记录不重复执行。草稿不上传服务器，也不视为持久项目记忆。

长答复默认显示前300字与“完整答复”，不改写原文，不把前段当重新生成的摘要。后台追加的机器证据ID与重复工作安排收进完整答复，答复依据仍从独立入口打开。当前待确认的目标、资源、权限和投入时长另以群聊内安排卡完整展示，不依赖展开答复才能审查。规划重复和状态通知用轻量提示显示；完整安排继续可打开。历史轮次、原始输入、模型输出、快照和证据未迁改。

显式的“资源：”与“额外要求：”无需模型调用即可整理成待讨论安排。它们继承目标和权限，只有用户同意后生效，不通过资源说明授权代码、访问或提高额度。

## 2026-10-08 的易用性迭代

参考 Grok Bot 的[长期角色与交接](https://docs.x.ai/grok-bot/bots)、[需要关注与工作状态](https://docs.x.ai/grok-bot/settings-and-notifications)，新增欢迎页起草入口、工具选择、待讨论安排卡和明确的成果/进展入口。工具选择发成聊天条件，确认前不启用权限；卡片确认绑定正在审查的提案编号，旧提案失效后不能误确认新的安排。沿用自然聊天，没有恢复必经会议页面。详细变化、实际发现的问题与验证限制见[三轮易用性记录](../reproductions/2026-10-08-human-design/REPORT.md)。
