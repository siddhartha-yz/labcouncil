# 复现与采用规则

创建日期：2026-10-04。任何候选框架目前都没有被选为 LabCouncil 的正式后端。

## 证据分别记录，不合并成“权威”标签

1. 出版信息：出版方记录、DOI、论文版本、同行评审情况、勘误与撤稿信息。arXiv 收录本身不是同行评审证明。
2. 作者证据：任务、数据、基线、模型版本、样本量、计算预算、统计方法、失败分母、代码与原始结果。
3. 外部证据：独立团队对同一版本和同一结论的复现。早期版本的批评或后续版本的成功不能相互替代。
4. 本地证据：我们实际执行的命令、环境、输入、输出、日志、失败、费用和结论边界。

期刊、机构和作者背景可以帮助安排阅读优先级，不能使代码功能、因果效果或本项目适用性自动成立。源码可读也不代表系统能运行。真实模型的行为不能由模拟模型的测试证明。

## 采用前的检查顺序

| 阶段 | 工作 | 通过之后能说明什么 |
| --- | --- | --- |
| R0 来源审计 | 固定论文与代码版本，提取可检验主张，检查公开数据、基线和许可 | 明确要验证的对象；尚未复现 |
| R1 环境与最小运行 | 固定依赖，运行官方最小示例，记录资源和全部错误 | 在该环境可运行；尚未证明科研效果 |
| R2 功能复现 | 逐项验证会议、证据落盘、干预、恢复、失败处理 | 被测组件或完整流程的具体功能成立 |
| R3 结果复现 | 按论文任务、模型、预算、种子和指标重复实验，比较基线 | 被测设置下的研究结果得到支持或未得到支持 |
| R4 项目适配评估 | 使用我们的计算任务，比较单 agent、无组会和人工组会 | 支持特定模块的集成决定；不代表全领域通用 |

R2 的组件检查不能标成 R3。环境不具备时记录“未运行／受阻”，不能记录“通过”或将其算作算法失败。

如果原论文模型不可用或预算不足，明确标成“改变条件的验证”，列出改变项。无法做湿实验的结果保持未复现。闭源系统只作为方法候选，第三方实现需另立记录。

## 首批复现对象与预注册条件

### Virtual Lab

先验证一场最小团队会议：使用固定议程和输入文件，保留每个角色的消息、总结、费用及版本；确认保存文件与讨论一致。另开一对一会议，要求指定来源的质疑能进入下一轮总结。

单次运行只用于检查流程。科研质量评估需使用多个任务和重复运行，记录全体结果及预先定义的判定标准。纳米抗体结果需要计算和湿实验，暂不纳入本平台首轮可完成的复现范围。

### freephdlabor

先检查无输入、修改当前任务、新任务、取消和输入中途断开的行为。随后用真实 agent 验证指令是否影响下一轮工具行为；保存后重启，比较目标、关键记忆、产物与计划，验证进程异常退出恢复，检测重复实验。

callback 返回、记忆被追加、模型执行了新任务和完整系统恢复，是四种不同主张，分别验收。现有组件检查脚本不会验证后两项。

### 科研效果比较

在同一组小规模计算任务、相同模型与工具、相同最大计算和 API 预算下比较单 agent、多个 agent 无人工组会、多个 agent 加人工组会。记录人工时间作为额外投入；不能把额外人力带来的提升归因于多 agent 本身。

提前固定任务、数据分割、基线、重复次数、指标和停止条件。保留负结果、失败运行、所有版本改动与偏离方案的原因。至少由人工检查关键结论与原始证据一致性。

## 每次运行的记录

为每个实验建立 `reproductions/<日期>-<对象>/`：说明目标与判定规则，保存代码 commit、文件哈希、依赖版本、输入、命令、原始输出、错误、费用、实际结果和解释。

运行开始前写预期和标准；结束后追加结果，不为迎合结果更换标准。一次修改或重试对应一条记录。公开仓库只提交脱敏后的材料，密钥不进入证据文件。

最终采用决定必须列出：验证了什么、未验证什么、存在的问题、为什么适用于 LabCouncil、是否采用以及需要补充的条件。也允许结论是暂不采用。
