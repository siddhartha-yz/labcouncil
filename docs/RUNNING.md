# 运行本地组会原型

这个版本已能走完：提交想法 → 后台三项任务 → 看报告和证据 → 追问 → 保存草稿 → 确认决定 → 下一轮继续。默认角色和问答由固定程序模拟；真实模式可选 Codex CLI（gpt-6.1-sol / high）或 DeepSeek Flash，负责工具参数、报告与组会答复。逐步研究模式根据已保存证据选择公开查询或整理组会；完整论文复现仍未接入。

## 开始使用

需要 Python 3.11 或更新版本。应用本身只有标准库依赖。默认模拟模式不用 API key；Codex 后台复用本机 `codex login`；只有 DeepSeek 后台读取仓库根目录被 Git 忽略的 `.env`。从仓库根目录执行：

```bash
python3 -m labcouncil start
```

然后打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。不要直接打开 HTML 文件。

`start` 在 Linux 上启动独立网页进程和 worker，重复运行会复用本实例。不会注册开机服务。每个实例使用独立运行目录；默认状态位于忽略的 `workspaces/labcouncil/`。

也可以各开一个终端，手动运行：

```bash
python3 -m labcouncil serve
python3 -m labcouncil worker
```

两个命令要使用同一个 `--database`。手动启动的进程用各自终端停止；`start/status/stop` 只管理带本实例标识的后台进程。

## Codex CLI 后台

Linux 上先安装 Codex CLI 并在终端完成 `codex login`。本机已验证 CLI 0.159.0、ChatGPT 登录和实际调用，不需要给网页填写新的 key。

新建研究群，在权限步骤选择“逐步研究”或“固定计算”，模型后台选择 **Codex CLI · gpt-6.1-sol · high**，明确勾选模型权限。后台按项目保存，下一轮继承；旧项目仍保留 DeepSeek 或模拟配置，不会被迁移成 Codex。需要比较两个后台时创建新群，避免同一项目混用供应商记录。

worker 每次通过参数数组运行 `codex exec`：`--model gpt-6.1-sol --config 'model_reasoning_effort="high"' --sandbox read-only --ignore-user-config --ignore-rules --ephemeral --json --output-schema ... --output-last-message ...`。提示由 stdin 传入；不改全局配置，不传入环境里的 API key，不保存原始 stderr。Codex 内置 shell、浏览器、插件、MCP apps、hooks 和子 agent 等能力关闭；它输出结构化参数，平台校验后执行原有有界工具。**这次是模型后端接入，不是开放任意仓库代码执行。** read-only 也不等于完整的文件读取隔离；以后开放代码执行需单独设计隔离工作区。

每次 CLI 启动前在 SQLite 占一个调用槽；后台与组会分别计量。一次启动可能包含多个内部模型 turn，CLI 自身可能处理连接恢复；启动次数上限不等于 API 请求数、token 或费用硬预算。CLI 返回的 input/output/cache/reasoning usage 保存，缺失保留未知，费用未知。规划和固定工具阶段最多120秒，研究报告与组会答复最多180秒；超时杀死进程组，失败占额度，不由平台自动重试或更换模型。Linux parent-death launcher 在 worker 消失时终止 CLI，租约过期按真实任务失败/未知处理。research 的 Codex 任务租约600秒、固定案例300秒，为两次CLI及原有短工具留出收尾时间。

每次任务和追问根据本轮输入、旧报告和固定证据重新构造上下文；CLI 会话是 ephemeral，项目记忆仍由 LabCouncil 的 SQLite 管理，不依赖 `resume --last`。保存 `thread_id`、正常化事件、最终 JSON 和用量；当前事件流不能独立证明服务端实际模型，证据是显式参数且无降级逻辑。

真实验收见 [Codex 后台记录](../reproductions/2026-10-07-codex-backend/REPORT.md)：两轮四步、一次实际组会答复、九次CLI启动，保留首次适配错误。方向确认由验收脚本完成，不能当作用户科研评审。

## 真实 Flash 合成案例

在本机 `.env` 配置 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL=deepseek-flash`，不要把 key 粘贴到项目想法或聊天里。新建研究群，在权限步骤选择“固定计算”和“DeepSeek Flash”后台。这会产生实际 API 请求与可能的费用。

第一轮选择干净数据；三个角色各执行两次模型请求：请求指定工具，再依据真实结果写报告。工具只有数据准备、回归计算、独立复算三项；40 个训练点、100 个独立测试点。组会确认“测试集含异常点：三次重复”后，第二轮测试标签约一成加入异常点，训练数据保持不变。自由文字决定会传给模型，但工具能力仍限于所选场景。

网页默认后台请求硬上限12；组会问答不设累计次数或模型请求次数上限，已有项目也适用。后台请求与角色任务单位分开计数；失败、超时和未知后台请求都占额度，不自动重试。后台额度建项目时设定，当前设置页不能提高后台真实请求额度。组会请求仍保存尝试、结果和用量，仍需授权模型调用，且只能向未结束的组会提问。旧数据库/API中的 qa_budget 与 qa_api_budget 保留兼容，但不再用于阻止问答。响应 usage 原样保存；缺失显示未知。每次输出上限768 tokens，不是整个项目 token 硬预算，人民币费用也保持未知。

报告中的“复核通过”仅表示数值从原始数据复算一致，**不能保证模型的每句话准确**。完整案例中，计算与复核角色把异常点数据误写成干净数据；原文仍保存，页面把实际工具输入并排显示。修订后的上下文会明确传入场景参数，但尚未再次用真实模型验证是否改善表述。

实际记录见 [完整案例](../reproductions/2026-10-06-complete-case/REPORT.md)。组会追问是实际 Flash 输出；Codex 点击确认的方向明确标为工程 fixture，不冒充你的科研评审。

## 五项输入与三步循环

主界面是默认多角色的研究群聊。先发送 idea，协调助手逐步询问资源、权限、每日时间和额外要求；最后确认后开始工作。角色分别汇报，工作条件、规划与报告通过消息附件打开，群聊设置在右上角“···”中。项目名称、调用上限和实验输入在权限步骤的“执行设置”中调整。

每天的工作时段按明确时区判断，开始时刻包含、结束时刻不包含，支持跨午夜。时段外不启动新任务，也不消耗新的角色任务单位；已启动任务可在租约内完成并保存。需要全天工作时明确勾选“全天可工作”。你可以在工作时段外读报告、开会和追问，追问仍受模型调用权限和组会状态限制，不设累计次数上限。

模型调用与已接入本地计算的权限会实际检查。research模式会实际检查公开研究权限。资源文字指导规划，不会自动挂载机器、文件或任意shell。

开组会后，点“下一轮方向”，五项输入带回上轮内容。保存草稿保留在数据库；确认才新增下一轮与任务。输入、固定执行计划和旧证据按轮次保留，不能修改已确认版本。当前模型上下文使用本轮输入节选、最近三份旧报告和最近两轮规划节选；完整原文持久化，但尚无模型按需检索完整项目记忆的工具。

群聊展示角色原始摘要，详细报告和核验范围通过附件打开；原始文字、数据和错误仍保留。simulation和real_case模式的计划由固定工具链生成；research模式每步的实际agent规划和理由独立保存。新闭环的实际网页验收见 [记录](../reproductions/2026-10-06-pipeline-alignment/REPORT.md)。

## 固定计算演示怎么用

1. 点击“＋”新建研究群，发送 idea，再随协调助手逐步确认五项输入。默认程序演示不调用模型。
2. 等本轮工作完成，在群里看研究员、实验员、复核员的摘要，点击消息附件审查详细报告和证据。
3. 点“开组会”，报告固定为开会时的版本；尚未完成的部分会注明。
4. 保存追问。演示模式使用引用快照的模板；讨论不派单。
5. 点“下一轮方向”，保留上轮资源和约束，调整要解决的问题。可先保存草稿，之后重新打开。确认后下一轮才开始。

自由文字方向会保存为指令；模拟程序只执行你选择的数据场景，不能自动实现文字描述的新实验。每轮保存三份证据和内容哈希。复核角色从原始输入用另一种公式复算；这是算术检查，不是科研效果评估。

## 预算、暂停与定时材料

后台角色任务与模型请求各自受上限约束；组会答复只记录累计次数，不设上限。执行一个角色消耗 1 个任务单位，后台任务达到上限就停止启动；可在项目设置中调整任务总上限。**这些单位不是 API token、人民币或 GPU 时间。**

暂停阻止新任务启动；已经开始的短任务仍可保存结果。设置组会时间使用浏览器本机时区，后台按 UTC 时间戳判断，到时生成固定快照。若服务离线，重新启动后补准备过期的材料；不会代你确认决定。本版只有平台内待审状态，尚无外部提醒或循环周历。

```bash
python3 -m labcouncil status
python3 -m labcouncil stop
```

停止保留数据库，重启读回任务、证据、组会、草稿、决定和真实请求额度。真实任务租约过期后标为失败、请求可能未知，不自动重新发送。第二轮起的工具结果在模型写报告前独立保存，即使报告失败也能读回；最初第一轮保存在角色原始证据中。过期租约可重算固定模拟任务，旧 worker 的写入被拒绝；每个任务最多提交一份产物。崩溃可能导致模拟计算被执行两次，不能把“一个提交结果”当成“外部实验绝不重复”。真正外部工具仍需稳定运行 ID 和独立恢复适配。

## 验证与限制

```bash
python3 -m unittest discover -s tests -v
node --check labcouncil/static/app.js
```

HTTP 和生命周期测试需要允许本机回环通信；所有应用测试都不调用真实模型；新增CLI可执行fixture测试覆盖进程、参数、事件、超时、权限、额度与迁移。供应商 HTTP fixture 测试覆盖预算并发、超时、429、未知用量、报告失败后保留工具结果和旧数据库升级。实际网页验收记录见 [M1 记录](../reproductions/2026-10-06-m1-prototype/REPORT.md)。

本版限于个人本机使用：绑定 `127.0.0.1`，检查 Host、Origin 和 JSON 请求来源，静态文件按明确清单提供。尚无公网身份认证、数据库迁移体系、外部进程监督或长周期稳定性验收。已接入受控案例的真实模型与请求次数预算；检索适配器已接入但公网稳定性仍未通过；隔离代码执行、token/人民币硬预算仍待完成；上游候选的采用状态单独保存在持续工作清单。

## 逐步研究模式（仍在验收）

新建时在权限步骤选择“Flash · 逐步研究”，明确勾选模型调用及公开查询权限。每天固定时段继续生效；本地计算权限可以不勾选。报告解释做了什么、发现什么、未完成项和下一步建议。每一步的规划、原因、真实工具状态、来源和模型原始响应在展开证据中。

目前工具范围：arXiv检索/摘要、GitHub搜索/固定commit README、自有OLS合成基准、准备组会。模型在这些动作中选择下一步，后台保存结果后才派下一步；每步2次模型请求，每轮最多6步，公开HTTP总上限建项目时可设0–24次，失败或未知均计入。默认不重试；明确勾选“连接失败后允许重试”时，每个URL整个项目最多三次尝试，2秒退避，仍受项目总上限约束。HTTP拒绝、证书校验失败、started/unknown不重试。连接方式、序号、耗时和结果留在账本。已成功操作跨轮去重；新一轮允许重试时可再检查前轮失败资料，同轮重复仍停止；关闭重试不丢失此前成功的缓存。公开资料不当作指令，不运行其中代码，不读取任意网址。

模型报告失败时，工具证据仍可审查，组会快照也保留当时已有工具记录。提示上下文标明节选，最多15000 UTF-8字节，完整原文保存在数据库；没有按需查询全部记忆的工具。

[真实验收](../reproductions/2026-10-06-research-loop/REPORT.md)确认逐步选择、失败留痕、自动停止、组会继承。公开查询多次TLS错误，前台独立检查只读到仓库元信息，未取得完整README。因此目前不能承诺公开检索稳定，更不能说论文已复现。

研究任务租约五分钟（固定案例仍为三分钟）。每步通常最多三次公开请求；明确允许连接重试时最多九次。arXiv仍全局串行并间隔三秒。达到公开读取额度后停止继续派任务，等组会审查；历史项目自动迁移默认24次，不改变模型额度和原有输入。

组会综合报告会固定本轮工具证据和最多3条前轮操作，每条发现可打开依据；更早记录仍在历史里。工具已保存而模型报告失败时，证据仍可引用。页面区分新读取和旧资料复用。报告与问答收到当前额度、权限及未接入工具信息，但引用有效不保证文字结论正确，仍需审查来源范围和建议是否可执行。
