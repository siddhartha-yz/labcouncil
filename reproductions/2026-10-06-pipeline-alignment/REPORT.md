# 五项输入与三步循环的前端对齐

2026-10-06。按用户明确的流程调整：**设定五项输入 → 后台工作与通俗报告 → 开组会 → 回到继承上下文的输入页**。工作时间采用用户确认的每天固定时段。没有增加头像、动画或虚拟房间。

这轮是产品流程与状态验收，使用固定程序执行器和合成数据，**没有真实模型请求**。不是通用研究能力验收，也不冒充实际用户科研评审。

## 已落地的变化

- 输入页包含 idea、可调用资源、权限、每日工作时间、额外要求。项目名称和执行器设置可展开，项目名可留空。
- 主页面突出本轮目标、状态、通俗报告和“开组会”。规划进度、资源约束、原始角色报告、证据与调用明细按需展开。
- 每轮输入和固定执行计划独立保存，确认后不可改写；组会快照关联当时版本。组会后回到同一输入表单，默认继承上轮内容。
- 五项输入草稿可以保存和重启恢复，不会创建任务；确认才产生下一版。重复确认不产生重复任务，改变已确认的资源或约束会拒绝。
- 每日时段使用明确时区，支持跨午夜。时段外不启动新任务、不消耗新角色单位；已启动任务可在租约内收尾。模型和已接入本地计算权限实际检查。
- 当前模型上下文加入本轮输入、最近三份旧报告和最近两轮规划的有限节选。原文完整保存在项目里，不宣称已具备按需检索全部研究记忆的工具。

报告首页的摘要是程序依据保存结果整理的，页面标明来源；原始模型文字没有被修改。完整产品要求见 [PRODUCT.md](../../docs/PRODUCT.md)。

## 实际网页做了什么

1. 新建工程演示项目，填五项输入：比较拟合误差、自有数据与本机工具、允许本地计算不允许模型、每日09:00–23:59（Asia/Shanghai）、先复算并保留历史。
2. 独立 worker 完成三个模拟任务。页面显示一份分为“做了什么、发现什么、还有什么没做、组会需要决定什么”的报告。
3. 开第一轮组会，保存一次明确标注的 Codex 工程问题，得到模板答复；讨论没有创建新轮次。
4. 点击“调整下一轮输入”，检查五项继承。修改目标、资源、公开研究授权记录、开始时间10:00及额外要求；固定计算输入选择异常点。保存草稿后仍是第一轮、三项任务。
5. 实际停止并重启本实例。重新打开组会与输入页，五项草稿和异常点选项恢复。整个项目状态、组会和草稿相同。
6. 在实际页面确认第二轮。同一项目ID新增输入与计划版本，worker 完成第二轮三个任务。第一轮输入、计划、证据、组会快照和讨论全部保留。
7. 重放完全相同的确认，返回原决定，任务总数仍为6，模型请求为0。

## 检查与边界

Python3.11与3.14各40项离线测试通过，见 [3.11](tests-python311.txt)、[3.14](tests-python314.txt)；JavaScript语法检查通过。新增检查涉及时区与跨午夜、时段外不扣额度、不阻塞其他项目、已开始任务收尾、权限拒绝、草稿恢复、版本冲突、旧数据兼容和HTTP接口。真实供应商仍以 HTTP fixture 代替，本轮零真实调用。JavaScript格式整理前后解析出的语法树一致。

一次浏览器自动化对带预填文本的 label 精确定位未命中；页面与草稿仍在，改用可访问 textbox 名称后完成操作。这是自动化定位失败，不计为产品状态丢失。

当前只有固定计算执行器，规划由程序生成；资源文字和公开研究权限只记录，不自动连接机器、挂载文件或执行检索。按资源与时间自主安排颗粒度、探索论文和仓库、选择复现任务、整理研究数据并持续自动 loop，是下一项核心交付，**尚未实现**。这次前端和状态闭环不能将第2步的科研能力标为完成。

日报时段、角色额度、请求次数是不同边界。token／人民币硬预算、任意代码沙箱、外部实验副作用恢复和长期研究效果仍未验收。新增控制逻辑只经离线 fixture 与实际模拟页面检查，未新增真实Flash验证。
