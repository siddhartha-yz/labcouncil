# 运行本地组会原型

这个版本已能走完：提交想法 → 后台三项任务 → 看报告和证据 → 追问 → 保存草稿 → 确认决定 → 下一轮继续。默认角色和问答由固定程序模拟；另有真实 Flash 合成案例模式，已完成两轮实际验收。两种模式都只执行预先定义的计算，不能按任意 idea 自动科研。

## 开始使用

需要 Python 3.11 或更新版本。应用本身只有标准库依赖。默认模拟模式不用 API key；只有明确选择真实案例时，调用进程才读取仓库根目录被 Git 忽略的 `.env`。从仓库根目录执行：

```bash
python3 -m labcouncil start
```

然后打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。不要直接打开 HTML 文件。

`start` 在 Linux 上启动独立网页进程和 worker，重复运行会复用本实例。不会注册开机服务。每个实例使用独立运行目录；默认状态位于忽略的 `workspaces/labcouncil/`。

也可以各开一个终端，手动运行：

```bash
python3 -m labcouncil serve
python3 -m labcouncil worker
```

两个命令要使用同一个 `--database`。手动启动的进程用各自终端停止；`start/status/stop` 只管理带本实例标识的后台进程。

## 真实 Flash 合成案例

在本机 `.env` 配置 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL=deepseek-flash`，不要把 key 粘贴到项目想法或聊天里。新建项目选择“真实 Flash：合成研究案例”。这会产生实际 API 请求与可能的费用。

第一轮选择干净数据；三个角色各执行两次模型请求：请求指定工具，再依据真实结果写报告。工具只有数据准备、回归计算、独立复算三项；40 个训练点、100 个独立测试点。组会确认“测试集含异常点：三次重复”后，第二轮测试标签约一成加入异常点，训练数据保持不变。自由文字决定会传给模型，但工具能力仍限于所选场景。

网页默认真实后台请求硬上限12、组会请求硬上限1，覆盖两轮与一次追问。与角色任务单位分开计数；失败、超时和未知请求都占额度，不自动重试。额度建项目时设定，当前设置页不能提高真实请求额度。响应 usage 原样保存；缺失显示未知。每次输出上限768 tokens，不是整个项目 token 硬预算，人民币费用也保持未知。

报告中的“复核通过”仅表示数值从原始数据复算一致，**不能保证模型的每句话准确**。完整案例中，计算与复核角色把异常点数据误写成干净数据；原文仍保存，页面把实际工具输入并排显示。修订后的上下文会明确传入场景参数，但尚未再次用真实模型验证是否改善表述。

实际记录见 [完整案例](../reproductions/2026-10-06-complete-case/REPORT.md)。组会追问是实际 Flash 输出；Codex 点击确认的方向明确标为工程 fixture，不冒充你的科研评审。

## 五项输入与三步循环

主界面围绕“设定本轮 → 后台工作与报告 → 开组会”。新建时填写 idea、资源、权限、每日时间和额外要求；项目名称、执行器与实验输入放在展开设置中。

每天的工作时段按明确时区判断，开始时刻包含、结束时刻不包含，支持跨午夜。时段外不启动新任务，也不消耗新的角色任务单位；已启动任务可在租约内完成并保存。需要全天工作时明确勾选“全天可工作”。你可以在工作时段外读报告、开会和追问，追问另受权限与额度限制。

模型调用与已接入本地计算的权限会实际检查。公开研究权限与资源说明先保存；当前没有文献／仓库自动探索，也不会由资源文字自动挂载机器、文件或任意 shell。

开组会后，点“调整下一轮输入”，五项输入带回上轮内容。保存草稿保留在数据库；确认才新增下一轮与任务。输入、固定执行计划和旧证据按轮次保留，不能修改已确认版本。当前模型上下文使用本轮输入节选、最近三份旧报告和最近两轮规划节选；完整原文持久化，但尚无模型按需检索完整项目记忆的工具。

报告首页展示程序整理的数值摘要与核验范围；角色原始文字和证据在展开项内，原始错误仍保留。当前计划由固定工具链生成，不冒充 agent 根据时间和资源自动规划。新闭环的实际网页验收见 [记录](../reproductions/2026-10-06-pipeline-alignment/REPORT.md)。

## 固定计算演示怎么用

1. 新建项目，填写五项输入。在“当前执行器与实验设置”中可选择流程演示；默认不调用模型。
2. 等本轮工作完成，阅读“做了什么、发现什么、还有什么没做、组会需要决定什么”。原始角色报告和证据按需展开。
3. 点“开组会，审查本轮报告”，报告固定为开会时的版本；尚未完成的部分会注明。
4. 保存追问。演示模式使用引用快照的模板；讨论不派单。
5. 点“调整下一轮输入”，保留上轮资源和约束，调整要解决的问题。可先保存草稿，之后重新打开。确认后下一轮才开始。

自由文字方向会保存为指令；模拟程序只执行你选择的数据场景，不能自动实现文字描述的新实验。每轮保存三份证据和内容哈希。复核角色从原始输入用另一种公式复算；这是算术检查，不是科研效果评估。

## 预算、暂停与定时材料

角色任务和组会答复分别计数；真实 API 请求另有上面说明的独立硬上限。执行一个角色消耗 1 个模拟任务单位，保存一次答复消耗 1 个模拟问答单位。达到上限就停止启动对应操作；可在项目设置中调整总上限。**这些单位不是 API token、人民币或 GPU 时间。**

暂停阻止新任务启动；已经开始的短任务仍可保存结果。设置组会时间使用浏览器本机时区，后台按 UTC 时间戳判断，到时生成固定快照。若服务离线，重新启动后补准备过期的材料；不会代你确认决定。本版只有平台内待审状态，尚无外部提醒或循环周历。

```bash
python3 -m labcouncil status
python3 -m labcouncil stop
```

停止保留数据库，重启读回任务、证据、组会、草稿、决定和真实请求额度。真实任务租约过期后标为失败、请求可能未知，不自动重新发送。第二轮起的工具结果在模型写报告前独立保存，即使报告失败也能读回；最初第一轮保存在角色原始证据中。过期租约可重算固定模拟任务，旧 worker 的写入被拒绝；每个任务最多提交一份产物。崩溃可能导致模拟计算被执行两次，不能把“一个提交结果”当成“外部实验绝不重复”。真正外部工具仍需稳定运行 ID 和独立恢复适配。

## 验证与限制

```bash
python3 -m unittest discover -s tests -v
node --check labcouncil/static/app.js
```

HTTP 和生命周期测试需要允许本机回环通信；所有应用测试都不调用真实模型；供应商 HTTP fixture 测试覆盖预算并发、超时、429、未知用量、报告失败后保留工具结果和旧数据库升级。实际网页验收记录见 [M1 记录](../reproductions/2026-10-06-m1-prototype/REPORT.md)。

本版限于个人本机使用：绑定 `127.0.0.1`，检查 Host、Origin 和 JSON 请求来源，静态文件按明确清单提供。尚无公网身份认证、数据库迁移体系、外部进程监督或长周期稳定性验收。已接入受控案例的真实模型与请求次数预算；检索、隔离代码执行、token/人民币硬预算仍属于 M2；上游候选的采用状态单独保存在持续工作清单。
