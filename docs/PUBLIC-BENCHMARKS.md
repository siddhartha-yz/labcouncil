# 公开科研agent测评：能借什么、怎样接

核查日期：2026-10-07。下面查阅了作者官方仓库或论文，**没有本地运行这些测评，没有给LabCouncil生成公开测评成绩**。作者的任务数量与评分说明不是我们独立核实的科学效果。

## 候选及适用范围

| 测评 | 作者公开的内容 | 对LabCouncil的用途 | 接入前要核对的边界 |
|---|---|---|---|
| [ScienceAgentBench](https://github.com/OSU-NLP-Group/ScienceAgentBench) | 原始套件102项、44篇论文，要求提交Python程序，有执行与评分工具 | 测“自己写科学分析代码，输出真实结果” | 作者2026-04-30发布verified版本修正误判；使用对应数据与评分资产。部分图像判分需要模型裁判；资产不能随意再公开分发 |
| [CORE-Bench](https://github.com/siegelz/core-bench) | 原始270项来自90篇论文，运行已有代码并回答结果问题 | 测依赖安装、实际执行和结果读取 | 原仓库建议使用HAL，旧harness不再积极维护；v1.1与OOD须和旧版分开。不同任务资源要求不同，先核对CPU任务 |
| [ResearchClawBench](https://github.com/InternScience/ResearchClawBench) | 仓库40项、10学科，提供数据与报告评价，已有Codex CLI入口 | 很贴近“做研究后给组会报告”；上海Lab候选可直接关联 | 评分使用文本/图像模型裁判，不是独立执行核验；仓库榜单取每任务最佳成绩，不能拿单次均值直接比较。HF额外16项不能混进原40项分母 |
| [MLAgentBench](https://github.com/snap-stanford/MLAgentBench) | 13项机器学习实验任务，提供起始环境、基线及隐藏评估脚本 | 测改代码、做实验、比较基线 | 成功率采用相对基线改进标准；任务的训练和数据要求逐项检查，不照搬早期模型排名 |
| [PaperBench](https://github.com/openai/frontier-evals/tree/main/project/paperbench) | 从零复现20篇ICML2024论文，逐项rubric评分 | 作为完整论文复现的后期目标 | 完整版在新环境执行提交代码，涉及GPU和较长时限；Code-Dev只评价代码，不能当完整复现成绩 |

版本补充：[CORE-Bench v1.1/OOD论文](https://arxiv.org/abs/2606.26158)也讨论效率、可靠性、模型与框架差异和人工协作；这些是作者研究结论，我们尚未复现。不要只取一项准确率就说平台已成熟。

本次新找到的[ResearchHarness](https://github.com/InternScience/ResearchHarness)是另一个轻量执行/测评候选。它不是LabCouncil当前依赖，尚未本地验证。InternAgent现有README将`sci_tasks`关联到ResearchClawBench，见[官方仓库](https://github.com/InternScience/InternAgent)。

## 为何目前还是两道自有题

原先先验收“工具真执行、数字可复算、组会确认能续派、失败和额度不丢”这些工程路径。自有合成题可控，适合发现流程缺陷；但这导致自主科研测量不足。此前上游会议、TCP干预、小工具和小计算试用都没有填补这个缺口。

当前执行器只支持摘要、README和预先实现的计算函数，不能直接承接上述要求生成并运行代码的任务。需要先接隔离执行器；不能把复制题目到提示里当成已接入公开测评。

## 第一轮接入建议：先固定题与评分，再测后端

这是准备协议，尚未执行：

1. 首选ScienceAgentBench verified中小规模、CPU可运行、可用确定性输出验收的任务。ResearchClawBench并行作为报告评价候选，不直接将其LLM总分当事实正确率。
2. 锁定代码commit、数据版本与哈希；建立候选任务清单，按数据大小、依赖、CPU/GPU要求筛选，**在模型执行前固定首批5项ID**。本次未核对逐任务资产，所以还没有确定这5个ID。此子集成绩不能冒充全套榜单成绩。
3. 先让参考提交通过，再做负面对照：缺结果、错误数值、只有文字自称成功、无法运行的代码。记录误接受和误拒绝，模型裁判另做人工抽查。不因作者或机构声誉跳过评分器验收。
4. 被测agent只看到题目和允许的数据；gold程序、隐藏测试、rubric和答案留在独立评分环境。限制读取评分仓库和查找直接答案，保留原测评约定。
5. 同题比较“Codex直接执行”和“LabCouncil调度Codex”；先固定相同模型、时长、工具、资源与重复次数。记录不同调用方式、全部失败和实际用量，不能用启动次数冒充内部模型请求数。
6. 公共题原生分数保持原定义；另外测组会后约束遵从、有效的新实验、重复执行和上下文保留。有人参与的条件记真实意见和时间，不能用Codex工程点击替代人工组。
7. 保留每次分项、均值和分布，不仅取最好一次；环境不兼容或资产缺失单列，不能静默删掉。评价报告事实准确率时逐条定义可核验主张、检查依据并记录漏报，不能只检查JSON引用。

公开测评补研究执行能力；自有组会与恢复测评补产品闭环。两类成绩分别展示，不把不同题目的分数平均成一个“科研总分”。
