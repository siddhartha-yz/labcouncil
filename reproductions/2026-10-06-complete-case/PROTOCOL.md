# 完整合成案例的实际模型验收

范围：平台中的真实 Flash 角色、三项允许工具、两轮工作、定时准备组会材料、快照追问、测试评审确认、后台继续、重启和重复确认。提前保存于首次真实 API 请求之前。不是原论文科研复现，不是任意 idea 的自主研究，也不是实际用户科研评审。

课题：少量测试标签异常点会怎样影响预测误差？第一轮 seed7，40训练点、100独立测试点，干净测试标签。第二轮 seeds7/19/31，训练数据不变，测试标签10%加入幅度10的异常点；保存平方误差、绝对误差和中位数绝对误差。基线只使用训练标签均值。

每轮资料、计算、复核三个角色均调用真实 deepseek-flash。每项先让模型请求唯一允许工具，严格核对参数后实际执行；再让模型依据真实工具返回写短中文报告。不得在模型请求前执行工具，不能把模型说“检查过”当复算。复核用另一个公式从已存原始数据和参数重新计算。

模型条件：Flash、thinking disabled、temperature0、每次输出最多768 tokens、输入最多20000 UTF-8字节、网络超时40秒、没有自动重试。新项目后台请求硬上限12、组会请求硬上限1；任一失败请求仍计入。额度持久化，发送前事务预留；usage缺失保留未知。token和人民币硬上限未实现，人民币费用未知。

真实模型参与研究报告和一次快照问答；人工意见用明确标注的 Codex 工程 fixture，通过真实页面确认，不计作用户评审。fixture：增加测试异常点、检查三个重复和多个误差指标，保留第一轮，不夸大结论。用页面问“这些结果能说明什么，还不能说明什么？”并检查证据引用。

开会只读固定快照；草稿、讨论不自动派单。确认后第二轮后台继续；重复原确认不增加任务。实际停止/启动新案例服务后检查证据、讨论、决定、真实请求额度和用量不变。

代码和数据为平台自有受控工具，没有执行模型生成的代码、查询论文或调用外部科学工具。真实任务中断后按未知处理，不自动重新发送；未验证副作用去重和远端已执行/本地未提交的崩溃窗口，不宣称M2/M3全部通过。

供应商fixture测试是离线工程检查，不能计入下面的真实模型请求。所有失败和协议修订另存尝试；不覆盖原始输出。

## 第一轮结果后的诊断追问增补

在真实请求6次后检查模型简报，发现“尚未多指标检查”与工具已返回三种误差指标不一致。保留原文，不修改历史报告；一次组会追问改为同时指出这处矛盾并询问结果的适用范围。这个修订在组会实际请求前写入，不再将原计划的泛问当作实际输入。
